# Перекройка сайта: главная, витрина, админка отдельным товаром, новости

12 августа 2026. Заказ владельца, четыре решения приняты им же (см. «Развилки»).

Это **спецификация**, а не отчёт: по ней правится код. Всё, что здесь названо
именем функции, столбца или класса CSS, — договор между файлами, и менять его
надо во всех местах разом.

## Развилки, решённые владельцем

| Вопрос | Решение |
|---|---|
| Что оставить в верху главной | Привилегии, Фараон **плюс** адрес и статус сервера |
| Срок админки | **Свой, независимый** от срока привилегии |
| Карточка уровня в витрине | Название, картинка, **цена**, кнопка |
| Новости | Лента на главной **плюс** страница-архив |

Два следствия, принятых мной и одобренных владельцем:

* с главной уходят кнопки «Купить привилегию» и «Пополнить кредиты» — они
  повторяют меню;
* из формы покупки уровня уходит флажок «плюс админка». Раз у админки свой
  срок, в одном заказе оказалось бы два разных срока. Заказ становится «один
  товар».

## 1. База

### 1.1 Новое: `zm_news`

```sql
CREATE TABLE IF NOT EXISTS `zm_news` (
  `id`           INT UNSIGNED NOT NULL AUTO_INCREMENT,
  `title`        VARCHAR(120) NOT NULL,
  `body`         TEXT         NOT NULL,
  `author`       VARCHAR(64)  NOT NULL DEFAULT '',
  `created_at`   DATETIME     NOT NULL,
  `updated_at`   DATETIME         NULL,
  `published_at` DATETIME         NULL,
  PRIMARY KEY (`id`),
  KEY `published_at` (`published_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

`published_at` тянет две обязанности разом: NULL — черновик, дата — новость
видна, и по ней же порядок в ленте. Отдельного «опубликовано: да/нет» нет
намеренно — два поля, отвечающих за одно состояние, рано или поздно разойдутся.

`body` — **обычный текст, никакого HTML**. Разметку собирает `news_html()`.

### 1.2 Изменения в `zm_privileges`

| Столбец | Было | Стало |
|---|---|---|
| `access` | буквы уровня **и** админки | **только** буквы уровня (или свои флаги из панели) |
| `expires_at` | срок всей записи | срок **уровня** |
| `has_admin` | TINYINT | удаляется |
| `admin_access` | — | **новый** VARCHAR(31) NOT NULL DEFAULT `''` — буквы админки либо пусто |
| `admin_until` | — | **новый** DATETIME NULL — срок админки |

Смысл NULL зависит от соседа, и это надо держать в голове:

* `access <> ''` и `expires_at IS NULL` → уровень навсегда;
* `admin_access <> ''` и `admin_until IS NULL` → админка навсегда;
* `admin_access = ''` → админки нет вовсе, `admin_until` не смотрим.

### 1.3 Представление `zm_admins`

Буквы собираются **на лету**, потому что сроков теперь два:

```sql
CREATE OR REPLACE VIEW `zm_admins` AS
  SELECT CAST(`auth` AS BINARY) AS `auth`, CAST(`password` AS BINARY) AS `password`,
         CONCAT(
           IF(`access` <> ''       AND (`expires_at`  IS NULL OR `expires_at`  > NOW()), `access`,       ''),
           IF(`admin_access` <> '' AND (`admin_until` IS NULL OR `admin_until` > NOW()), `admin_access`, '')
         ) AS `access`,
         `account` AS `flags`
  FROM `zm_privileges`
  WHERE (`access` <> ''       AND (`expires_at`  IS NULL OR `expires_at`  > NOW()))
     OR (`admin_access` <> '' AND (`admin_until` IS NULL OR `admin_until` > NOW()));
```

Запись попадает серверу, пока жив **хотя бы один** из двух сроков.

⚠️ Склейка безопасна ровно потому, что буквы уровня (`t s q p o`) и буквы
админки (`b c d e i j u`) не пересекаются: повторов не будет. Худшая длина —
21 буква своих флагов плюс 7 админки = 28, а плагин читает `access` в буфер на
32 байта. Запас есть, но он не бесконечен: добавляя буквы, пересчитайте.

⚠️ Своими флагами из панели админка **не** дополняется — `api.php` уже сейчас
ставит `with_admin` только при пустых своих флагах. Это правило сохраняется.

### 1.4 `zm_orders`

```sql
`kind` ENUM('tier','packs','admin') NOT NULL DEFAULT 'tier'
```

Столбец `with_admin` **остаётся** — в нём история старых заказов. Новые заказы
его не пишут; в панели он показывается только у заказов, где он равен 1.

### 1.5 Файлы

* `sql/schema.sql` приводится к итоговому виду — для чистой установки.
* `sql/migrate-2026-08-12.sql` — для базы, где уже что-то есть. Переносит
  `has_admin = 1` в `admin_access` и `admin_until = expires_at`, вычищает буквы
  админки из `access`, пересоздаёт представление и только потом роняет
  `has_admin`. Порядок значим: сначала перенос, потом удаление источника.

## 2. `private/app/tiers.php`

Убрать: `const ADMIN_PRICE`, `function access_flags()` (её работа распалась на
`tier_flags()` и `ADMIN_FLAGS`).

Изменить: `price_of($tierId, $days)` — третьего аргумента больше нет.

Добавить:

```php
function admin_terms()            // те же ключи, что terms(): 30, 90, 0
function admin_prices()           // array(30 => 149, 90 => 349, 0 => 699)
function admin_price_of($days)    // int | null
function admin_powers()           // что админка ДАЁТ, см. ниже
function admin_denied()           // чего она НЕ даёт, список строк
```

`admin_powers()` возвращает список
`array('letter' => 'c', 'name' => 'Кик', 'desc' => '…')`. Содержимое сверено с
`amxconst.inc` и `custom/plugins/zp_admin_limits.sma`:

| Буква | Название | Что делает |
|---|---|---|
| `b` | Резерв места | зайти на сервер, когда он полон |
| `c` | Кик | выгнать игрока |
| `d` | Бан | **не дольше 30 минут и не чаще трёх раз за карту**; вечный бан невозможен в принципе |
| `e` | Слей | убить нарушителя на месте, не выгоняя |
| `i` | Админ-чат | переписка админов, недоступная остальным |
| `j` | Голосования | запускать голосование за карту или кик |
| `u` | Админ-меню | `amxmodmenu` — всё перечисленное через меню |

`admin_denied()`: неприкосновенность к чужим админам, смена карты, правка
настроек сервера, выполнение конфигов, пароль сервера, rcon.

⚠️ Числа «30 минут» и «три раза за карту» — это `zp_admin_ban_max` и
`zp_admin_ban_permap` из `zp_admin_limits.sma`. Меняя их там, поменяйте здесь.

## 3. `private/app/grant.php`

### 3.1 `merge_grant($existing, $tierIndex, $days, $wantAdmin, $adminDays, $dbNow)`

Возвращает:

```php
array(
  'tier'         => int,      // -1 — уровня нет
  'access'       => string,   // буквы уровня
  'expires'      => ?string,  // срок уровня; null — навсегда
  'admin_access' => string,   // '' либо ADMIN_FLAGS
  'admin_until'  => ?string,  // срок админки; null при непустом admin_access — навсегда
)
```

Правила — прежние по духу («покупка никогда не ухудшает положение»), но
считаются для двух сроков **раздельно**:

* уровень берётся наивысший из старого и нового;
* `$tierIndex === null` означает «уровень не трогать»: старые `access` и
  `expires_at` переносятся как есть;
* срок уровня прибавляется к остатку, и «навсегда» с любой стороны делает срок
  вечным;
* админка: `$wantAdmin` включает её и прибавляет `$adminDays` к остатку
  `admin_until` ровно тем же правилом; `$adminDays === 0` — навсегда;
* `$wantAdmin === false` оставляет уже купленную админку нетронутой — доплата
  за уровень не должна отбирать админку, и наоборот.

### 3.2 `grant_privilege($opts)`

Новые и изменённые ключи: `days` — срок уровня, `admin_days` — срок админки,
`with_admin` — включить админку, `tier_index` — `null` значит «уровень не
трогать».

Проверка «не выбрано ничего» переезжает: ошибка, если после слияния **и**
`access`, **и** `admin_access` пусты.

В `INSERT`/`UPDATE` вместо `has_admin` идут `admin_access` и `admin_until`.

Возвращаемый массив получает `admin_access` и `admin_until` вместо `admin`.

### 3.3 `privileges_list()`

Добавить к каждой строке: `adminUntil`, `adminLeft` (суток, как `left`),
`adminExpired`, `adminForever`. Ключ `admin` теперь `boolean` от
`admin_access <> ''`. `expired` и `left` относятся к **уровню**.

Сортировка учитывает обе жизни: строка, у которой протух уровень, но жива
админка, не должна падать в конец списка как мёртвая.

### 3.4 `apply_order()`

Три ветки вместо двух: `packs`, `tier`, `admin`.

Ветка `admin` зовёт `grant_privilege()` с `tier_index => null`,
`with_admin => true`, `admin_days => (int)$order['days']`.

Ветка `tier` больше не передаёт `with_admin`.

## 4. `public/buy.php`

`kind_of` принимает `tier | packs | admin`.

Для `admin`: срок проверяется по `admin_terms()`, сумма — `admin_price_of()`,

## 5. `private/app/view.php`

`nav_items()` получает пункт между «Сервер» и «Привилегии»:

```php
'news' => array('href' => 'news.php', 'label' => 'Новости'),
```

Две новые мелкие функции — чтобы карточка витрины могла быть кликабельной
целиком, не пряча внутри себя вторую кнопку:

```php
/** data-атрибуты окна просмотра, отдельно от разметки. */
function viewer_attrs($modelId, $title = '', $desc = '', $extra = null, $panelId = '')

/** Просто картинка модели, без своего окна: щёлкать будет карточка снаружи. */
function model_img($modelId, $class = '')
```

`viewer_attrs()` отдаёт строку вида
` data-model="…" data-title="…" data-desc="…" data-extra="…" data-panel="…"`,
пропуская пустое. `viewer()` переписывается на неё же — снаружи она ведёт себя
как прежде, и `index.php` с `shop.php` менять не нужно.

## 6. `public/assets/viewer.js`

Окно становится двухколоночным.

```html
<div class="mv-box" role="dialog" aria-modal="true">
  <button class="mv-close" type="button" aria-label="Закрыть">×</button>
  <div class="mv-title"></div>
  <div class="mv-cols">
    <div class="mv-left">
      <div class="mv-stage"><canvas></canvas><div class="mv-note"></div></div>
      <div class="mv-desc"></div>
      <div class="mv-picks"></div>
    </div>
    <div class="mv-side"></div>
  </div>
</div>
```

Три новых правила и ни одного больше — просмотрщик не должен знать про магазин:

1. `boot()` цепляется к `[data-model], [data-panel]`, а не только к первому.
2. Есть `data-panel="tpl-x"` → содержимое `#tpl-x` (это `<template>`)
   клонируется в `.mv-side` при каждом открытии. Нет — `.mv-side` прячется и
   `.mv-cols` получает класс `solo`.
3. Нет `data-model` → `.mv-left` прячется, WebGL не поднимается вовсе,
   `.mv-cols` получает `solo`. Окно только с текстом — законный случай: у
   админки модели нет.

Щелчок по элементу с атрибутом `data-mv-close` внутри окна закрывает его. Всё
остальное, что происходит в правой колонке, — дело страницы: она вешает свой
обработчик на `document` и видит щелчки по клонированному узлу обычным
всплытием. Так просмотрщик остаётся ничего не знающим о ценах и уровнях.

⚠️ Клонировать надо **при каждом открытии**, а не один раз: иначе второе
открытие покажет узел, из которого предыдущее уже могло что-то стереть.

## 7. `public/privileges.php`

### 7.1 Витрина

Вместо `<label class="item">` — сетка `.tier-cards` из `<article class="tier-card">`:
название, картинка облика, «от N ₽», кнопка «Подробнее». Карточка кликабельна
целиком (`role="button"`, `tabindex="0"`), атрибуты от `viewer_attrs()`,
`data-panel` указывает на `<template>` этого уровня.

### 7.2 Что крутится в окне

Полоса `.mv-picks` для уровня — накопительно, как и права: облик самого
уровня, затем облики, ножи и классы зомби этого уровня и всех младших.
Облики младших добавляются **впервые** — `zp_skins` проверяет бит, и старший
уровень действительно может их надеть, а покрутить их до сих пор было негде.

### 7.3 Правая колонка

`<template id="tpl-tier-vip">` и так далее, по одному на уровень. Внутри:

* «Что даёт на сервере»: кредиты за возрождение, здоровье, облик, число ножей
  и их названия, класс зомби с числами (HP, скорость, прыжок, отбрасывание);
* напоминание про накопительность;
* цены по трём срокам;
* кнопка `<button data-mv-close data-pick-tier="vip">Выбрать этот уровень</button>`.

Ещё один шаблон — `<template id="tpl-admin">`: `admin_powers()` таблицей,
`admin_denied()` списком, цены, кнопка
`<button data-mv-close data-pick-admin="1">Купить админку</button>`.

### 7.4 Секции, которые уходят

«Ножи, которые открывает уровень» и «Классы зомби, которые открывает уровень»
удаляются целиком. Всё их содержимое живёт теперь в окне.

### 7.5 Секция «Админка»

Между витриной уровней и формой заказа. Одна широкая карточка `.admin-card`:
название, короткое описание, «от 149 ₽», кнопка «Подробнее» —
`data-panel="tpl-admin"`, `data-model` нет.

### 7.6 Форма заказа

Одна на страницу. Сверху переключатель товара:

```html
<div class="seg" id="what">
  <button data-v="tier"  aria-pressed="true">Уровень</button>
  <button data-v="admin" aria-pressed="false">Админка</button>
</div>
```

* `tier` — как сейчас: сроки из `terms()`, цены из таблицы уровней;
* `admin` — блок выбора уровня скрыт, сроки из `admin_terms()`, цены из
  `admin_prices()`, в счёте строка «админка».

Скрытое поле `kind_of` следует за переключателем. Флажок `with_admin`
удаляется вместе с его строкой в счёте.

Делегированный обработчик на `document` ловит `data-pick-tier` и
`data-pick-admin`, ставит форму в нужное состояние и прокручивает к ней.

## 9. `private/app/news.php` (новый)

```php
news_latest($limit = 5)          // опубликованные, свежие первыми
news_page($limit, $offset)       // опубликованные, для архива
news_published_count()
news_all()                       // всё, включая черновики — для панели
news_by_id($id)
news_save($id, $title, $body, $author)  // $id === 0 → создать; вернуть id
news_publish($id, $on)           // published_at = NOW() либо NULL
news_delete($id)
news_html($body)                 // текст → безопасная разметка
news_excerpt($body, $chars = 200)
```

`news_html()` работает **строго в таком порядке**, и порядок здесь — это и есть
защита:

1. `h()` — экранировать целиком, до всякого разбора;
2. разбить по пустым строкам на абзацы, одиночный перевод строки — `<br>`;
3. в уже экранированном тексте найти `https?://[^\s<]+`, отрезать хвостовую
   пунктуацию (`.,!?;:)»…`) и обернуть в
   `<a href="…" rel="noopener noreferrer nofollow">`.

Экранировать после разбора нельзя ни в каком виде: тогда собственные теги
разметки съедаются вместе с чужими, а стоит их пощадить — и щель для чужого
скрипта открыта.

## 14. Чем проверяется

* `php -l` на каждом изменённом файле.
* Представление `zm_admins` отдаёт правильные буквы в четырёх случаях: жив
  только уровень, жива только админка, живы оба, не жив ни один (строки нет).
* Покупка админки поверх действующей привилегии **не двигает** срок привилегии,
  и наоборот.
* Страницы отвечают 200, а `buy.php` без POST по-прежнему уводит на главную.
