# Аудит готовых сборок CS 1.6 Zombie Plague

Дата: 2026-08-04. Проверено 6 пакетов, 14 000+ файлов.

## Как проверялось

Восемь слоёв: антивирус, сверка SHA256 с официальными релизами, разбор
скомпилированных `.amxx` (распаковка контейнера, таблица нативов, строковый пул),
разбор исходников `.sma`, построчный разбор `users.ini`, конфиги, скрипты запуска,
строки нативных модулей.

Инструменты написаны в `tools/` и работают без интернета.

## Калибровка

Сканеру, который не проверен на заведомо известных ответах, верить нельзя.
Поэтому прогонялись контроли:

| контроль | что это | ожидалось | получено |
|---|---|---|---|
| `sekys-cs-amxpackage` | пакет с задокументированным бэкдором | грязно | **dirty, 26 критических** |
| `calibration` | плагин, собранный нами из кода той же закладки | грязно | **dirty, 6 критических** |
| `zp-selfbuilt` | Zombie Plague, скомпилированный нами из апстрима | чисто | **0 критических, 0 высоких** |
| `gamemodd-zp44fix5a` | исходники Zombie Plague от автора мода | чисто | **0 критических, 0 высоких** |
| официальные плагины AMXX | 54 плагина трёх версий | чисто | **0 находок** (совпадение по хэшу) |

Двусторонняя проверка сошлась: заражённое краснеет, чистое остаётся чистым.

Правила калибровались итеративно. Отброшены как ложные: строка `system` в
бинарнике (есть почти в каждой программе на C), `abcdefghijklmnopqrstuvwxyz`
(алфавит в тесте, а не флаги доступа), `exec cfg/мод.cfg` (штатная загрузка
конфига), закомментированные примеры в `users.ini`, наличие `hlds.exe` как
такового.

## Главная находка: админы в комплекте

Во **всех** проверенных сборках `users.ini` содержит рабочие учётные записи.

**cs-rage (самая свежая, 2021):**

```
"r0"   ""  "abcdefghijklmnopqrstuv"  "ek"
"XxXx" ""  "deu"                     "e"
"r1"   ""  "peu"                     "e"
"r2"   ""  "deu"                     "e"
"r3"   ""  "teu"                     "e"
"r4"   ""  "zeu"                     "e"
```

Флаг `e` означает «пароль не проверять». Достаточно зайти на сервер под ником
`r0` — и вы полный администратор. Пароль не нужен. Пять дополнительных записей
работают так же. Это не уязвимость, а вход, оставленный намеренно.

**zombie-dev:** `"xman2030" "1" "abcdefghijklmnopqrstu" "a"` — аккаунт автора
сборки с паролем `1` и всеми правами.

**cs-hlds 2010:** `"admin" "admin" "abcdefghijklmnopqrstu" "a"` — учётные данные
по умолчанию, известные каждому из 9 913 скачавших.

**kriansa/cs-16-server** (эталонный «чистый» репозиторий с GitHub, MIT-лицензия):

```
"loopback"           ""  "abcdefghijklmnopqrstu"  "de"
"STEAM_0:0:53506913" ""  "abcdefghijklmnopqrstu"  "ce"
```

SteamID автора репозитория с полными правами и без пароля. Развернёте как есть —
автор администратор на вашем сервере.

## Прочие находки

- **Плагины без исходников:** 10 из 37 (cs-hlds), 6 из 36 (zombie-dev).
  Содержимое таких `.amxx` недоказуемо: пересобрать и сверить нечем.
- **Посторонние бинарные модули:** `ALX_LowPing.dll`, `Booster` — нативные
  библиотеки, работающие с полными правами процесса сервера, вне песочницы AMXX.
- **Непроверяемые исполняемые файлы:** `hlds.exe`, `hltv.exe`, `WinCSX.exe`,
  `amxxpc.exe` не совпадают ни с одним официальным релизом. Скорее всего это
  просто старые версии, но подмена движка выглядит ровно так же.
- **Антивирус:** Защитник Windows не нашёл угроз ни в одной сборке. Это
  ожидаемо — закладки в CS 1.6 живут в конфигах и байт-коде плагинов, а не в
  сигнатурах вредоносных программ.

## Что удалось и не удалось скачать

Две самые популярные сборки недоступны: файлы `all-cs.net.ru` (137 790
скачиваний) и `cs-hlds.ru / kto_to` (3 941) лежали на Яндекс.Диске и удалены —
API отдаёт 404 при живых страницах-описаниях. Их популярность подтверждена, но
проверить нечего.

## Вывод

Ни одна готовая сборка не годится для запуска как есть. При этом ни в одной не
найдено кражи данных или связи с ботнетом — реальная проблема оказалась проще и
неприятнее: **авторы сборок оставляют себе доступ**, а сборку скачивают тысячи
человек, и доступ получают все они.

Из сборок можно безопасно брать «мёртвый» контент — модели, звуки, карты,
спрайты — и исходники `.sma` после чтения. Всё исполняемое берётся из апстрима.

Собранный по этому принципу сервер лежит в `server/` и проверен тем же сканером:
0 критических, 0 высоких, `users.ini` пуст.
