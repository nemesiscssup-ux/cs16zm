# Что поменять на игровом сервере

Четыре правки. Первые три не трогают игру, зомби-мод и уровни — меняется только
то, **откуда** сервер берёт список администраторов. Четвёртая нужна лишь тем,
кто продаёт кредиты.

Правки НЕ применены к сборке намеренно: над ней в это же время работает другой
агент, и вслепую менять общий `tools/assemble.mjs` значит рискнуть его прогоном.
Здесь описано ровно то, что надо сделать, и почему именно так.

## Почему это безопасно

`admin.amxx` и `admin_sql.amxx` — это **один и тот же плагин**, собранный
дважды: с `#define USING_SQL` и без него
(`upstream/reference/amxx-1.10.0-git5479/addons/amxmodx/scripting/admin.sma`).
Загружать надо ровно один из них.

Ключевое свойство SQL-варианта — он **сам откатывается на `users.ini`**, если до
базы не достучался:

```pawn
if (sql == Empty_Handle)
{
    server_print("[AMXX] %L", LANG_SERVER, "SQL_CANT_CON", error)

    //backup to users.ini
    ...
    loadSettings(configsDir) // Load admins accounts
    return PLUGIN_HANDLED
}
```

Значит переключение не может отрезать владельца от сервера: упал сайт, легла
база, ошиблись в пароле — сервер просто читает прежний `users.ini`, как читал.
Поэтому правку можно применять до того, как база настроена.

## 1. Переключить плагин

В `configs/plugins.ini` нужно, чтобы вместо

```
admin.amxx		; admin base (required for any admin-related)
;admin_sql.amxx		; admin base - SQL version (comment admin.amxx)
```

было

```
;admin.amxx		; admin base (required for any admin-related)
admin_sql.amxx		; admin base - SQL version (comment admin.amxx)
```

Файл **собирается** `tools/assemble.mjs` (раздел «конфигурация»), поэтому править
готовый `server/cstrike/addons/amxmodx/configs/plugins.ini` бесполезно — правка
исчезнет при следующей сборке. Менять надо в `assemble.mjs`, рядом с тем местом,
где он уже правит `modules.ini`. Строка-замена:

```js
// Админов берём из базы сайта, а не из users.ini: только так у привилегии
// появляется срок действия — просроченная запись просто перестаёт попадать
// в выборку. При недоступной базе admin_sql сам читает users.ini, поэтому
// переключение не может запереть владельца снаружи.
const withSql = cur
  .replace(/^admin\.amxx/m, ';admin.amxx')
  .replace(/^;admin_sql\.amxx/m, 'admin_sql.amxx')
```

⚠️ Проверка `tools/verify-ru.mjs` читает порядок загрузки из собранного
`plugins.ini` — убедитесь, что она не считает `admin.amxx` обязательным.

## 2. Прописать базу

Файл `configs/sql.cfg` — готовый лежит рядом (`sql.cfg`). Подставьте настоящие
хост, базу, пользователя и пароль.

⚠️ **Заведите для игрового сервера ОТДЕЛЬНОГО пользователя MySQL с правом только
`SELECT` на представление `zm_admins`.** Сейчас у сайта пользователь с полными
правами на базу; положив его пароль в `sql.cfg`, вы кладёте полный доступ к базе
сайта на игровой хостинг, где файлы видит и поддержка хостинга, и любой, кто
получит доступ к панели игрового сервера. Пользователь заводится в ISPmanager
(«Базы данных» → пользователи), права выдаются запросом:

```sql
GRANT SELECT ON `ваша_база`.`zm_admins` TO 'игровой_пользователь'@'%';
```

Представление называется `zm_admins`, а не `admins`, потому что таблица
`admins` в этой базе уже занята соседним сайтом. Имя задаётся кваром
`amx_sql_table`, так что плагину всё равно — важно лишь, чтобы они совпадали.

## 3. Модуль MySQL

Ничего делать не нужно — `mysql_amxx_i386.so` уже лежит в `modules/`, а AMX Mod X
подгружает модули по требованию плагина. Убедиться можно в логе сервера при
старте: строка `[AMXX] Loaded N admins from database` означает, что связь есть.

Если в логе `SQL_CANT_CON` — сервер не дотянулся до базы. Частые причины:
хостинг режет исходящий 3306, либо пользователь MySQL заведён без `@'%'`.

## Как проверить, что сработало

1. В панели сайта выдайте себе VIP на 30 дней.
2. В логе игрового сервера должно появиться `Loaded ... admins from database`
   (после `amx_reloadadmins` — панель шлёт его сама).
3. Зайдите на сервер, введите в консоли `setinfo _pw "выданный_пароль"`.
4. `amx_who` в консоли сервера покажет вас с флагами уровня.

## Что НЕ меняется

* `zp_vip.sma`, `zp_skins.sma`, `zp_knives.sma` — они читают `get_user_flags()` и
  не знают, откуда админ взялся;
* `custom/admins.ini` и локальная панель `admin.cmd` — остаются как запасной
  вход. Держите там учётку владельца: это ровно тот список, на который сервер
  переключится, если база станет недоступна.

# 4. Команда начисления кредитов (для магазина кредитов)

Нужна, только если продаёте кредиты. Без неё магазин работает, но оплаченные
заказы ждут в панели, и начислять их приходится руками.

## Почему нельзя обойтись готовой `zp_packs`

Она **устанавливает** баланс, а не прибавляет к нему:

```pawn
zp_set_user_ammo_packs(target, amount)
```

То есть команда `zp_packs Вася 500` не «выдаст 500 кредитов», а сделает баланс
Васи равным 500 — стерев всё, что он заработал за вечер. Для выдачи админом это
удобно, для покупки — недопустимо.

Прочитать баланс снаружи тоже нечем: `zp_progress_show` печатает только ключи и
признак загрузки, но не число кредитов. Поэтому «прочитать и записать сумму»
собрать не из чего.

## Что добавить

В `custom/plugins/zp_shop_weapons.sma`, рядом с регистрацией `zp_packs`:

```pawn
    register_concmd("zp_packs_add", "cmd_packs_add", ADMIN_LEVEL_A,
        "<ник> <сколько> - ПРИБАВИТЬ кредиты (для покупок на сайте)")
```

И сам обработчик — рядом с `cmd_packs`:

```pawn
// Прибавка, а не установка. Разница принципиальная: этой командой пользуется
// сайт после оплаты, и затирать ею заработанное игроком нельзя.
public cmd_packs_add(id, level, cid)
{
    if (!cmd_access(id, level, cid, 3)) return PLUGIN_HANDLED;

    new who[32], amount_s[12]
    read_argv(1, who, charsmax(who))
    read_argv(2, amount_s, charsmax(amount_s))

    new amount = str_to_num(amount_s)
    if (amount < 1 || amount > 999999)
    {
        console_print(id, "сколько прибавить? ожидается от 1 до 999999")
        return PLUGIN_HANDLED;
    }

    new target = cmd_target(id, who, CMDTARGET_ALLOW_SELF)
    if (!target)
    {
        // Сайт узнаёт по этому ответу, что игрок вышел, и оставляет заказ
        // ждать. Менять текст нельзя, не поправив deliver_packs() на сайте.
        console_print(id, "игрок «%s» не найден", who)
        return PLUGIN_HANDLED;
    }

    new was = zp_get_user_ammo_packs(target)
    zp_set_user_ammo_packs(target, was + amount)

    new name[32]
    get_user_name(target, name, charsmax(name))
    zlog("КРЕДИТЫ: игроку %s прибавлено %d (было %d)", name, amount, was)
    console_print(id, "прибавлено %d, у %s теперь %d", amount, name, was + amount)
    client_print_color(target, print_team_default,
        "^x04[ZP]^x01 Начислено ^x04%d^x01 кредитов. Всего: ^x04%d", amount, was + amount)

    return PLUGIN_HANDLED;
}
```

Затем в `/private/config.php` на сайте:

```php
'shop' => array('packs_command' => 'zp_packs_add'),
```

## Ограничение, которое никуда не денется

Начислить можно **только игроку, который сейчас на сервере**: команда ищет его
по нику среди подключённых, а баланс вышедшего лежит в nvault сервера, куда
снаружи хода нет. Поэтому на странице магазина прямо написано «зайдите на сервер
и оставайтесь на нём», а заказ, который не удалось выдать, остаётся в панели со
статусом «оплачен, не выдан».
